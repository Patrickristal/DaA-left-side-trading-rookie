## 第一层：信号源 — 预测应基于什么

### 信号源 #1：政策驱动 + 兑现时间点

**核心思路**：未来一个**确定的政策兑现时间点**是预测最硬的支撑。比起"政策利好"这种模糊话，"X 月 Y 日前 Z 万亿要下达"是可证伪的硬节点。

**当下例子**（截至 2026-04-17）：
- 4 月 17 日发改委：合计 **1.755 万亿元**（中央预算内投资 + 超长期特别国债）要求 **6 月底前完成下达**
- 投向：新型能源体系 / 城市更新 / 国家水网 / AI 配套基建
- 兑现时点：6 月底前
- 受益方向：新能源 / 城投基建 / 水利工程 / 数据中心

**预测怎么用**：
- 锁定时间窗：6 月底前（资金到位）+ 后续业绩兑现 6-12 月（产业类时滞）
- Base case 概率支撑：政策资金已落地 = 受益板块超额收益概率 高 (>60%)
- 翻转触发：资金到位时间延期 / 投向比例调整 / 监管口径反转

**调用模块**：M5 政策影响分析为主，M4 引用为证据

**数据源 hookup**：AKShare `news_cctv` / `stock_info_global_cls` / `news_economic_baidu` + Patrick 上传的政策文件链接

### 信号源 #3：资金面 / 流动性信号

**核心思路**：钱从哪来，要去哪。资金行为先于价格，**资金转向通常领先趋势 1-3 周**。

**信号清单**：

| 信号 | 数据源 | 领先性 | 解读 |
|---|---|---|---|
| 北向 5/20 日累计 | AKShare `stock_hsgt_*` | 1-3 周 | 外资态度（最干净） |
| 两融余额 | AKShare `stock_margin_*` | 1-2 周 | 杠杆情绪 |
| ETF 申赎 | 公开公告 / Wind | 1-2 周 | 中长资金动向 |
| 龙虎榜机构 / 知名游资席位 | AKShare `stock_lhb_*` | 1 天-1 周 | 短线资金 |
| 大宗交易溢价率 | AKShare `stock_dzjy_*` | 1-2 周 | 减持 / 增持信号 |
| 央行 OMO / MLF / RRR / LPR | AKShare `macro_china_*` | 1-3 月 | 流动性总闸 |
| 南向资金（港股） | AKShare `stock_hsgt_*` symbol="南向" | 1-3 周 | 内资态度 |
| 沽空比率（港股） | AKShare `stock_hk_short_*` | 1-2 周 | 反向情绪 |

**预测怎么用**：
- **资金共振**：≥ 2 个信号同向 + Z-score ≥ 1.5 → 趋势延续概率 高
- **资金背离**：信号撕裂 → 反转预警，重新评估论点
- 时间套利：资金转向后 1-3 周内是高 alpha 进出场窗口

**调用模块**：M6 三资金趋势模块为主

### 信号源 #4：基本面拐点 + 业绩预期差

**核心思路**：每个标的或行业有 1-2 个**关键变量**决定股价方向。预测时识别这个变量的拐点信号；同时关注 "**市场一致预期 vs 你的判断**" 的差距 — 超额收益来自**预期差**，不是来自共识。

**关键变量按行业**：

| 行业 | 关键变量 | 拐点信号 | 数据源 |
|---|---|---|---|
| 光伏 | 硅料价格 | 周环比转正、库存去化 | 工信部 / 硅业分会 |
| 储能 | 电芯价格 + 装机量 | 月度装机环比、电芯利润率 | 国家能源局 |
| 白酒 | 动销 + 库存 | 渠道库存周转、批价 | 公司 + 渠道调研 |
| 消费 | CPI / 社零 | 月度同比、PMI 消费分项 | 统计局 |
| 房地产 | 销售面积 / 投资 | 月度同比 | 统计局 + 30 大中城市 |
| AI | Token 消耗 / 推理需求 | 主要厂商财报披露 | 公司财报 |
| 半导体 | 设备 capex + 国产替代率 | 季度 capex 同比 | 公司财报 + SEMI |
| 银行 | NIM + 不良率 | 半年报披露 | 公司财报 |
| 互联网 (HK) | 广告 + 游戏流水 + 云收入 | 季度财报披露 | 公司财报 |
| 半导体 (HK) | 产能利用率 + ASP | 季度披露 | 公司财报 |

**预期差怎么用**：
- **市场一致预期**来源：Wind / Choice 分析师一致预测（**这是 AKShare 数据缺口** — 需 Patrick 上传研报或财经终端截图）
- **你的判断**：基于上述拐点信号 + AKShare 数据
- 差距 > 20% → 高 alpha 机会，但**反过来也可能是你判断错** — 必须用方法 #5（多视角对抗）压力测试

**调用模块**：M2 因子注册表 + 财报数据 + Patrick 上传的研报

## 第二层：方法 — 用什么思维框架

### 方法 #2：Reference Class Forecasting (参照类预测)

> Tetlock 在 *Superforecasting* 中将此方法定为超预测者使用最频繁的工具。核心是：**先看类似情况发生过多少次、结果如何，再看当下有什么不同**。

**三步法**：

1. **找类似情境**：在历史上找 **3-5 个最相似** 的 setup（政策环境、估值水位、资金结构、宏观背景）
2. **基础概率 (Base Rate)**：在这些历史 setup 中，X 类型事件发生了 M 次 / 共 N 次 = M/N
3. **当前差异调整**：列出当前与历史的关键差异，每个差异**调整 5-15 pp**

**例子**（"海洋工程板块 2026-2027 跑赢沪深300 ≥ 8pp" 命题）：

```
类似先例 (N=3)：
- 2013 一带一路：发布后 6 个月，受益板块超额表现 +25%
- 2017 雄安新区：发布后 3 个月超额 +30%，6 个月退潮
- 2021 储能十四五规划：发布后 6 个月超额 +15%

基础概率 = 3/3 = 100% (规划发布后 6 个月内出现 ≥ 8pp 超额)

当前差异调整：
- (a) 海工资金到位速度比一带一路慢 → -10pp
- (b) 央企订单已实锤兑现，比雄安单纯主题强 → +5pp
- (c) 地缘催化更强（周边纠纷推升 "海洋利益"）→ +5pp
- (d) 大盘整体环境一般，β 弱 → -5pp

调整后：仍属"高"档（>60%），但因 N=3 样本太少，不给精确小数概率。
```

**关键纪律**：
- **N < 5 时不给精确小数概率**，只给"高 / 中 / 低"分类
- 列出的先例必须**真实存在 + 可查证**，不许编造
- 当前差异列 **3-5 条**，不要堆量

### 方法 #5：多视角对抗 (Actively Open-Minded Thinking)

**核心**：把信念当**假设**不当**身份**。强迫自己同时写"为什么会涨"+"为什么会跌"，然后衡量两边证据强度。

**落地**：M4 reference 已实现 — 3 阶段对抗辩论（看多研究员 → 看空研究员 → 风控员），空方必须**先逐条反驳多方再独立挖反方**。

**关键纪律**：
- 即使 Patrick 抛出强空命题（如"全面危机近在咫尺"），主动找 **3 条多方证据反驳**
- 即使分析后偏多，保留 **3 条空方证据**供 Patrick 持续监控
- **空方挖不出来要明说**，不能凑数；穷尽搜索后空方仅有 X 条且较弱要写明

### 方法 #6：概率化 + 贝叶斯更新

**Forward 输出**：不给二元答案（"会涨 / 会跌"），给概率。

**Bayesian update**：每次新信息出现时，**主动**评估应该让概率往哪调多少。

**例子**（"上证 6 月底前突破 3500"命题）：

```
初始判断 (2026-05-01)：基于 setup A → 概率 50%
新信息 1 (2026-05-10) 4 月 PMI 50.5 高于预期 → 上调 5pp → 55%
新信息 2 (2026-05-12) 北向连续 5 日净流出 30 亿 → 下调 8pp → 47%
新信息 3 (2026-05-15) 政治局会议提"加大逆周期调节" → 上调 10pp → 57%
新信息 4 (2026-05-25) 美元利率超预期上行 30bp → 下调 5pp → 52%
...
```

**关键纪律**：
- 每次新信息**显式宣告**调整方向 + 幅度 + 理由
- 全部写入 `memory/forecasts.jsonl` 留痕
- 这避免**屁股决定脑袋**（buy 后只看利好的 confirmation bias）

### 方法 #7：Fermi 估计 (拆解问题)

**核心**：把模糊大问题拆成**可估计的小问题**。每个子问题更容易给概率，组合起来就是大问题答案。

**例子**（"A 股 2026 下半年怎么走？"）：

```
拆解：
1. GDP 增速？(预测 +5.0% ± 0.3%) → 概率分布
2. 流动性松紧？(M2 同比 +X% / LPR 是否下调) → 概率分布
3. 地产能否企稳？(销售面积同比由负转零的概率) → 概率分布
4. 美联储几次降息？(FOMC dot plot + market implied) → 概率分布
5. 业绩预期？(沪深300 EPS 同比预期) → 概率分布
6. 海外冲击？(地缘 / 大选 / 债务危机) → 概率分布

每个子问题独立估概率 + base rate
组合：用各子问题概率加权 → 大问题答案分布
```

**何时用**：
- 时间尺度 ≥ 1 个季度的预测
- 涉及多变量的预测
- 复杂宏观预测

### 方法 #5 + #6 + #7 的关系

这三个方法互相配合：
- #7 把大问题拆小 → 在每个小问题上用 #5 找正反证据 → 用 #6 给概率并随新信息更新

## 第三层：元规则 — 怎么让预测"诚实"

### 元规则 #8：边界条件与黑天鹅

**纪律**：每个预测必须**显式声明** 3 项：

1. **前提条件**：什么必须为真，预测才成立（如"美联储不超预期加息"）
2. **失效条件**：什么发生，预测必须**重写**（如"6 月地产销售环比再降 10% 以上"）
3. **黑天鹅**：可能颠覆预测的低概率高影响事件（如"霍尔木兹封锁"、"主要交易对手断交"、"系统性金融风险"）

**落地**：M4 的 trend-break triggers 是失效条件的具体形式。每个 forecast 必须配 **3-5 个 triggers**。

> 预测不仅是给结论，更是给"什么情况下我会改变结论"。

### 元规则 #9：时间尺度区分

**Tetlock 研究**：预测准确度随时间尺度急剧下降 — 一年以内还能比较准，超过一年准确率大幅降低，超过两年接近随机。

**纪律**：

| 时间尺度 | 可给输出 |
|---|---|
| **周内** | 区间预测（如上证 3300-3450）+ 关键事件 + 不给小数概率 |
| **月内** | 情景化（base/bull/bear）+ 概率区间（5pp 精度） |
| **季度内** | 情景化 + 概率小数（带方法论支撑） |
| **半年至一年** | 情景化 + 概率分类（高 >60% / 中 30-60% / 低 <30%） |
| **1-2 年** | 方向 + 关键变量 + 边界条件（不给概率） |
| **2 年以上** | 方向性判断 + 主要风险（不给概率，不给精确目标） |

**关键纪律**：
- **不要**用一套逻辑回答两个时间尺度的问题
- 时间越长，概率区间越宽
- 显式标注预测的时间尺度

### 元规则 #10：事后复盘 (校准)

> Tetlock 核心：**没有复盘的预测只是赌博，有复盘的预测才能持续进步。**

**留痕 schema** (`memory/forecasts.jsonl`)：

```json
{
  "forecast_id": "fc_20260501_001",
  "timestamp": "2026-05-01T17:30:00+08:00",
  "subject": "上证综指 2026 Q3 突破 3500",
  "scenario": "base",
  "probability": 0.55,
  "probability_range": [0.50, 0.60],
  "time_horizon_end": "2026-09-30",
  "time_scale": "quarter",
  "key_assumptions": ["...", "...", "..."],
  "trend_break_triggers": ["...", "...", "..."],
  "linked_thesis_id": "thesis_20260501_xxx",
  "linked_module": "M4",
  "signal_sources_used": [1, 3, 4],
  "methods_used": [2, 5, 6],
  "bayesian_updates": [
    {"date": "2026-05-15", "delta_pp": +10, "reason": "政治局会议", "new_prob": 0.65}
  ],
  "resolution_date": "2026-10-01",
  "resolved": false,
  "actual_outcome": null,
  "brier_score": null
}
```

**校准过程**：
- 每个预测到 `resolution_date` 自动检查实际结果
- 计算 **Brier score**：`(predicted_probability - actual_outcome)²`，越小越准
- 月度 / 季度生成 **校准报告**：你说 60% 概率发生的事，实际是不是大约 60% 时间发生了？

**校准报告示例**：

```
2026-05 校准报告（截至 2026-04-30）：

总预测数：23
已 resolved：12
平均 Brier score：0.18（< 0.25 算合格，< 0.10 算优秀）

按概率分桶：
- 50-60% 桶 (4 个预测)：实际发生 2 次，命中率 50%（与预测概率匹配）✅
- 60-70% 桶 (5 个预测)：实际发生 4 次，命中率 80%（高于预测概率，倾向 underconfident）
- 70-80% 桶 (3 个预测)：实际发生 1 次，命中率 33%（远低于预测概率，倾向 overconfident）⚠

按信号源分类胜率：
- #1 政策驱动 (8 个)：胜率 75%
- #3 资金信号 (3 个)：胜率 67%
- #4 基本面拐点 (1 个)：胜率 100%（样本太小）

倾向性诊断：
- 70%+ 概率桶 overconfident — 下次给高概率时强制保留 3 条空方证据
- 政策类预测最稳定，可作为 anchor
- 资金信号预测命中率虽然 67%，但都是短期预测（1-2 周），符合资金领先性研究
```

**落地**：
- M4 每次 forecast 自动写入 `memory/forecasts.jsonl`
- M3 复盘交易时附带检查相关 forecast 是否实现
- 每月底自动跑校准检查（**Cowork scheduled task** 实现）

## 反模式（这套方法特别容易踩的）

- ❌ **没有信号源就给概率** — 必须显式标注 #1/#3/#4 哪几个用了，不能凭空
- ❌ **小样本 (N<5) 给精确小数** — 必须用"高/中/低"分类
- ❌ **时间尺度混淆** — 用周级别证据回答季度级别问题
- ❌ **没有边界条件** — 每个预测必须配失效条件
- ❌ **没有 Bayesian 更新机制** — forecast 写入后再不更新 = 静态预测，不是 Bayesian
- ❌ **不写入 memory** — 没有留痕的预测是赌博
- ❌ **只列正方证据** — 强制 #5 多视角对抗
