# M4 — 观点验证 & 思路深挖 (Insight Verification & Devil's Advocate)

这个模块是 Patrick 工作流的**起点**：他先有一个论点（基于研究 / 直觉 / 板块观察），扔给技能，技能用对抗式辩论 + 立场矩阵把论点压力测试，然后把论点正式**登记**为活跃监测对象，下游模块（M1 prep、M3 复盘）持续跟踪条件破损。

读完 SKILL.md 后再读这份。本模块大量借鉴 [TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN) 的多代理辩论架构 + [vnpy](https://github.com/vnpy/vnpy) 的 PositionWatcher 思路。

---

## 模块契约 (Module Contract)

- **Standalone trigger**：Patrick 说 "我觉得 XX 要…"、"我有个想法"、"帮我看看这个判断对不对"、"反驳一下我"、"还有什么角度"、"这个逻辑站得住脚吗"。也可以由用户主动说"登记一个论点"触发。
- **Composition role**：作为增强模块嵌入 M2 / M1 时，提供 `立场矩阵` 小节 — 对当前关注的票/板块做 steelman + redteam 浓缩版（4-5 行）。完整辩论流程只在 standalone 时跑。
- **Inputs needed**：
  - 必需：Patrick 的论点（哪怕一句话也行）
  - 强烈推荐：论点关联的标的、板块、时间窗
  - 可选：他已经掌握的支持论据、当前是否已建仓、目标仓位
- **Outputs produced**（标准小节，其他模块可引用）：
  - `## 论点解读` — 翻译成可证伪命题
  - `## 多方论据` — 3 条最强证据（看多研究员）
  - `## 空方论据` — 必须先反驳多方，再加 3 条新增（看空研究员）
  - `## 立场矩阵` — 5×3 表格（5 维度 × 多/空/净倾向）
  - `## 综合立场 & 信号强度` — 0-10 强度 + 立场标签
  - `## 关键观察指标` — trend-break triggers（4-5 条可观测事实）
  - `## 历史相似论点回顾` — 从 memory store 检索（可选）
  - `## 论点登记` — 写入 `memory/active_theses.jsonl`，激活下游监测
- **Common compositions**：
  - **+ M5（政策证据）**：政策面证据由 M5 提供具体文件/会议引用
  - **+ M6（资金证据）**：资金面证据由 M6 调用 AKShare 拉北向 / 主力 / 融资数据
  - **+ M2（技术面证据）**：技术面证据由 M2 调用 K 线和因子
  - **被 M3 反向调用**：M3 复盘已平仓交易时，调用 M4 历史登记还原"当时的论点是什么、破损条件是什么、哪条先破"

## 触发场景

Patrick 通常这样开场：
- "我觉得**储能**要起来" / "我看好**半导体国产替代**这条线"
- "**腾讯**这个位置我觉得可以加" / "**中芯国际**是不是要 breakout 了"
- "**美元利率**如果继续走低，对**港股科技**应该是利好吧"
- "**新型储能行动方案**这个文件落地，**储能逆变器**应该最受益"
- "反驳一下我这个想法" / "我可能想偏了，帮我看看"

输入有时只有一句话，有时附加他的论据 / 截图 / 链接。**没附加 = 用户期望你不仅评判他给的，还要主动找他没给的（多方证据 + 空方证据他都可能漏）。**

## 设计原则（这个模块的灵魂）

### 1. 反向偏置 (Reverse Bias) — 主动找空方证据
人类天然有 confirmation bias，Patrick 抛过来的论点他自己已经找过支持证据了。**技能的高 leverage 不在重复他想到的，而在挖他没想到的。** 因此：
- 多方证据：限制在 3 条最强，不要堆量
- 空方证据：先**逐条反驳**多方 3 条，再**新增** 3 条独立反方 — 总共空方至少 6 条触点
- 空方挖不出来 = 论点确实强，但要明确说"穷尽搜索后空方仅有 X 条，且较弱"，不能糊弄

### 2. 多代理角色分工（借鉴 TradingAgents-CN）
内部模拟三个角色，输出时显示其工作产出：
- **看多研究员 (Bull Researcher)**：找最强支持证据，按基本面 / 技术面 / 资金面 / 政策面 / 情绪面分类
- **看空研究员 (Bear Researcher)**：必须先反驳看多，再独立挖反方
- **风控员 (Risk Manager)**：填立场矩阵，给综合立场 + 信号强度 (0-10) + trend-break triggers

不要把三个角色合并成一段散文。**结构性分离**让 Patrick 一眼看出哪部分是支持哪部分是反驳，方便他选择性深挖。

### 3. 不替 Patrick 决策
即使空方完胜，输出**只标注立场倾向 + 信号强度**，不写"建议不要进"。Patrick 说他要 second opinion，不要 verdict。

### 4. 论点登记 = trend integrity 条件登记
关键创新：M4 输出的"关键观察指标"就是 M1 / M3 用的 **trend integrity 条件**。Patrick 接受论点 → 论点登记 → 4-5 条条件写入 memory → 之后每次 prep 自动勾选 → 哪条破了立刻报告。
这把 SKILL.md 五原则之一的"trend integrity 监测，不强制纪律"落到具体机制。

### 5. 命题必须可证伪
"储能要起来" 不是可证伪命题。**翻译成**："未来 1 个季度，储能板块跑赢沪深300 ≥ 5pp，且板块内龙头单只涨幅 ≥ 30%。" 加时间窗 + 量化目标 + 比较基准。论点登记前必须翻译。

## 数据获取（按需调用其他模块）

M4 不直接拉数据，而是调度其他模块：

```
论点接收 → 解析关键标的/板块/时间窗
  ↓
分发任务到证据收集层:
  - 基本面 / 估值 → AKShare `stock_a_indicator_lg`、`stock_financial_em` (财报)
  - 技术面 → 调用 M2 的 factor 计算器（scripts/ta_factors.py），输入标的，输出命名因子值
  - 资金面 → 调用 M6 的三资金读取器（scripts/fund_flow.py），输入标的/板块
  - 政策面 → 调用 M5 检索 (scripts/policy_search.py)，输入关键词 + 时间窗
  - 情绪面 → 调用 scripts/xueqiu_fetch.py 拉关注度变化 + AKShare 龙虎榜
  ↓
看多研究员: 在每个维度选最强 1 条证据（最多 3 维度共 3 条）
  ↓
看空研究员: 逐条反驳 + 在每个维度找反方 1 条
  ↓
风控员: 整合矩阵 + 综合立场 + trend-break triggers
  ↓
（可选）写入 memory/active_theses.jsonl
```

具体脚本封装在 `scripts/` 中，M4 内部不应自己写 AKShare 调用，而是调用模块封装。

## 6. 情景化预测 (Scenario Forecast)

风控员基于立场矩阵给出 **base / bull / bear** 三档情景。**必须遵循 `references/forecasting-discipline.md` 的完整方法论** — 该文件给出 10 角度框架（信号源 #1/#3/#4 + 方法 #2/#5/#6/#7 + 元规则 #8/#9/#10）和标准输出模板，是 SKILL.md 原则 1 的具体执行手册。

每次 forecast 必须显式标注：
- 用了哪些信号源（#1 政策 / #3 资金 / #4 基本面）
- 用了哪些方法（#2 Reference Class / #5 多视角对抗 / #6 概率+Bayesian / #7 Fermi 拆解）
- 时间尺度（依元规则 #9 选择 — 周/月/季/年）
- 边界条件（#8 — 前提 / 失效 / 黑天鹅）

并把 forecast 写入 `memory/forecasts.jsonl` 留痕，配合元规则 #10 的月度校准（Brier score 检查）。

| 情景 | 概率区间 | 关键假设（3-5 条 + 数据源）| 量化目标（区间）| 翻转触发器 |
|---|---|---|---|---|
| **Base** | 50-60% | (1) [假设 + 数据源] (2) [...] (3) [...] | [点位区间 / 涨幅 / 时间窗] | [可观测条件] |
| **Bull** | 20-25% | (1) [...] (2) [...] (3) [...] | [...] | [...] |
| **Bear** | 20-25% | (1) [...] (2) [...] (3) [...] | [...] | [...] |

**概率支撑**（必须给出方法论，否则只能用"高 / 中 / 低"分类）：
- **历史频率法**：在过去 N 次类似 setup 中（具体年份），出现 X 类型的有 M 次 = M/N（基础概率）
- **情景调整**：根据当前与历史先例的关键差异（如 [具体差异]），上调 / 下调 [幅度]
- **引用来源**：[历史样本来源，如 AKShare 历史数据回溯 + 政策文件名]

**精度约束**（重要 — 反占星）：
- 概率给区间不给单点（✅ "50-60%" / ❌ "55%"）
- 量化目标给区间不给单点（✅ "上证 3300-3700" / ❌ "3500"）
- 时间窗给区间不给日（✅ "2026 Q3-Q4" / ❌ "10 月 15 日"）
- 没有方法论支撑就用 "高 (>60%) / 中 (30-60%) / 低 (<30%)" 分类，不要虚构

**何时跳过此节**：如果论点本质是定性判断（"应不应该重仓某只票" — 这是仓位决策），跳过情景预测；只在论点蕴含**未来走势 / 时间窗 / 概率**时填本节。

## 反模式（这个模块特别容易踩的）

- ❌ **奉承式回答** — Patrick 说"我觉得 X 要起来"，你回 "确实，X 看起来不错"。这是 confirmation bias 放大器。强制保留空方至少 6 条触点（3 反驳 + 3 新增）。空方挖不出来要明说，不要凑数。
- ❌ **散文化的辩论** — 把多方/空方融成一段流水话。结构性分离不能省。
- ❌ **不可证伪的命题** — 没翻译成"时间窗 + 量化目标 + 比较基准"就开始辩论 = 后期无法复盘。强制翻译。
- ❌ **trend-break triggers 写得太软** — "如果情绪转变就退出" 不算条件。必须**可观测 + 数值阈值 + 时间窗**（如"周线收盘跌破 60MA"、"5 日北向净流出超 5 亿"）。
- ❌ **强加纪律** — "建议不要进" / "应该立刻平仓"。换成 "立场倾向 + 信号强度 + 你需要决定..."
- ❌ **遗漏维度** — 5 维度（基本面 / 技术面 / 资金面 / 政策面 / 情绪面）必须每个都有一格证据，哪怕写"该维度证据不足"。空着 = Patrick 不知道是没分析还是真的没证据。
- ❌ **机械凑齐 5×3 矩阵** — 如果某维度真的中性，写"中性 / 0"，不要硬塞证据扭曲结论。

## 何时应该问 Patrick 而不是自己决定

- **论点过于模糊**（"我觉得最近行情不错"）：问 "这个判断你想聚焦在哪个板块 / 哪只票 / 什么时间窗？"
- **论点已蕴含具体仓位动作**（"我准备买 30 万 XX"）：问 "这是想我帮你验证论点本身，还是验证仓位规模合理性？两个不一样"
- **trend-break triggers 不确定 Patrick 接受**：登记前问一句 "这 4 条 trigger 你都同意吗？还是要改？"
- **memory 里有强相关历史论点但情境有变**：问 "我看到 YYYY-MM-DD 你做过类似判断，结果是 [...]。这次的关键差异是 [...] 吗？"

## 与其他模块的协作

### M4 → M1 的接力（核心闭环）
- M4 完成登记 → 写入 `memory/active_theses.jsonl`
- 每次 M1 盘前 / 盘后跑时，加载所有 active theses，对每个登记标的检查 trend-break triggers
- 任一触发，M1 输出在 `你的雷达` 小节标注 ⚠️：
  > **储能板块论点 (thesis_20260415_03)** — trigger #2 触发：北向 5 日累计净流出 -6.3 亿（阈值 -5 亿）

### M4 ← M3 的反馈（学习闭环）
- M3 复盘已平仓交易时，调用 M4 的历史登记
- 找到该标的对应的 thesis，对比 entry/exit 时间点的 trigger 状态
- 在 M3 输出补一段：哪条 trigger 真的预警了？哪条 trigger 误报？哪条该有但没设？
