# M3 — 交易日记 & 持仓复盘 (Trade Journal & Post-Trade Review)

这个模块帮 Patrick 把每一笔交易转化成**可学习的洞察**。Patrick 说他会日常上传东方证券截图，技能从截图提取事实，与 M4 论点登记对比，输出**决策质量评估**（不是结果好坏评估）+ 经验标签累积。

读完 SKILL.md 后再读这份。本模块借鉴 [TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN) 的 Reflection 模块（结构化 post-mortem 累积学习）+ pyfolio 的 tear sheet 思想 + [vnpy](https://github.com/vnpy/vnpy) 的 trade log schema。

## 模块契约 (Module Contract)

- **Standalone trigger**：Patrick 上传东方证券截图（持仓 / 成交 / 盈亏统计 / 带交易标记的 K 线） + "复盘"、"这笔操作怎么样"、"昨天那波我做错了吗"、"今日调仓总结一下"。
- **Composition role**：作为增强模块嵌入 M1 / M4 时，提供 `复盘卡片` — 5-8 行精简版（最近一次操作 + 决策质量评分 + 一个经验标签）。
- **Inputs needed**：
  - 必需：东方证券截图（一张或多张），或文字陈述的交易（"昨天卖了 XX，价 X，理由 X"）
  - 强烈推荐：交易对应的论点 ID（如 `thesis_20260415_03`），用于和 M4 登记对比
  - 可选：Patrick 主观描述（"当时是因为板块跳水我恐慌了"），帮助分类经验标签
- **Outputs produced**（标准小节）：
  - `## 截图事实提取` — 从截图里读出的客观信息
  - `## 交易归档` — 结构化 trade record (JSON-friendly schema)
  - `## 论点对照` — 与 M4 论点登记 + trigger 状态对比
  - `## 决策质量评估` — 区分"决策对 vs 结果好"
  - `## 经验标签` — 从预定义 taxonomy 里选
  - `## 学习要点` — 1-3 条 take-away，写入 memory
  - `## 关联历史` — 同标签历史交易回顾（仅当 memory 有相关记录）
- **Common compositions**：
  - **+ M2（技术面回看）**：在 entry / exit 时点叠加 K 线，看当时因子读数
  - **+ M4（论点回看）**：调用 M4 历史登记，对照 entry 时论点 → exit 时哪条 trigger 触发
  - **+ M6（资金面回看）**：entry / exit 时点的三桶状态，验证资金流向是否提示了拐点
  - **嵌入 M1 盘前**：以 `## 昨日复盘要点` 形式开篇

## 设计原则（这个模块的灵魂）

### 1. 决策质量 ≠ 结果好坏
Patrick 应该最先听到的话：**"赚了不一定决策对，亏了不一定决策错。"**

随机性占短期收益很大权重。复盘应该评估的是 **决策时点**：
- 当时论点是否成立？
- entry / exit 触发是否符合预先登记的 trigger？
- 仓位规模是否匹配信号强度？
- 信息利用是否完整？

如果 Patrick 因为正确执行计划而亏钱，这是**好决策 + 坏结果**，不需要修正。
如果 Patrick 因为情绪或随机因素赚钱，这是**坏决策 + 好结果**，要警惕（这是危险路径）。

### 2. 与 M4 论点登记闭环（核心机制）
M3 复盘的最高价值在**对照 M4 登记**：
- Entry：当时是基于哪条论点 (thesis_id)？登记的 trigger 是哪 4 条？
- 持有期间：trigger 状态有没有破损？M1 prep 提示过没有？
- Exit：是哪条 trigger 触发了 exit？还是凭情绪 / 其他原因？

如果 Exit 不是因为 trigger 触发，分类为 "**无理由 exit**"（往往是过早止盈），这是 Patrick 自我诊断的核心痛点。

### 3. 经验标签累积，不止于本笔
每次复盘必从 **预定义 taxonomy** 选 0-3 个经验标签（不是自由发挥，而是固定一组词汇，方便累积）。同一标签出现 ≥ 3 次 = 系统性问题，需要专项关注。

### 4. 不羞辱 Patrick
Patrick 是有经验的成熟交易者。复盘语气保持中立分析师，不要：
- "你这次操作错得离谱" → 改为 "这次 exit 时 trigger 状态尚未破损，提前止盈"
- "你应该听我的" → 改为 "M1 prep 在 [日期] 提示过 trigger #2 已经偏离..."

### 5. 截图事实提取诚实
看不清的字段 = 看不清。直接说 "持仓成本这一栏分辨率不够，能再发一张高清的或者文字告诉我"。**不靠猜数字。**

### 6. 不规劝下一步操作
- ❌ "建议下次类似情况立刻平仓"
- ✅ "这次 exit 触发条件是 [情绪]，与登记 trigger 不一致。下次可考虑 entry 时把 [情绪] 也写入 trigger 列表 / 或保留更严格的机械规则"

把"下次怎样"作为可选方案给 Patrick，不强加。

## 东方证券截图字段映射

> ⚠ **第一次使用前需要 Patrick 上传一张样本截图**确认字段位置。这里给一个**通用骨架**，会在 Patrick 实际上传后调整。

### 常见页面 1：持仓页

| 字段 | 通常位置 | 数据格式 | 用途 |
|---|---|---|---|
| 股票名称 + 代码 | 每行最左 | "腾讯控股 00700" | 标的识别 |
| 持仓数量 | 第 2 列 | 整数 | 仓位规模 |
| 持仓成本 | 第 3 列 | 元 / 港币 | 计算盈亏点 |
| 现价 | 第 4 列 | 当前价 | 实时盈亏 |
| 当日涨跌幅 | 第 5 列 | % | 日变动 |
| 浮动盈亏 | 第 6 列 | 元 / 百分比 | 累计盈亏 |
| 持仓占比 | 第 7 列（可能折叠）| % | 仓位结构 |
| 股票市值 | 第 8 列 | 元 | 用于占比计算 |

### 常见页面 2：当日成交记录 / 历史成交

| 字段 | 通常位置 | 用途 |
|---|---|---|
| 成交时间 | 最左 | 时点判定 |
| 股票名称 + 代码 | 第 2 列 | 标的 |
| 买/卖方向 | 第 3 列 | 操作方向 |
| 成交数量 | 第 4 列 | 仓位变动 |
| 成交价格 | 第 5 列 | entry / exit 价 |
| 成交金额 | 第 6 列 | 资金占用 |
| 手续费 | 第 7 列（可能展开）| 真实净成本 |

### 常见页面 3：盈亏统计 / 资金账户

| 字段 | 用途 |
|---|---|
| 总资产 | 总览 |
| 可用资金 | 当前现金 |
| 当日盈亏 | 当日变动 |
| 累计盈亏 | 累计表现 |
| 收益率（周 / 月 / 年） | 时间维度对比 |

### 常见页面 4：带交易标记的 K 线

如果 Patrick 上传带买卖箭头的 K 线，提取：
- 买点 / 卖点的日期 + 价格
- 当时 K 线状态（接近高点 / 低点 / 中段）
- 周期（日线 / 周线）

> **校准协议**：Patrick 第一次上传时，技能输出 "我从这张图读到的字段是 [...]，正确请确认；不正确请告诉我哪一列对应什么。" 一次校准后写入 `assets/dongfang_screenshot_layout.md`，后续直接用。

## 经验标签 Taxonomy (固定 12 个标签)

每次复盘从这 12 个里选 0-3 个，**不要发明新标签**：

| 标签 | 定义 | 触发条件 |
|---|---|---|
| **追高** | entry 时价格已脱离合理介入区 | entry 价距 20MA > +15% 或距 60MA > +30% |
| **止损过紧** | exit 时趋势未破，因短期波动恐慌出 | exit 时 trigger 未触发 + 当周内回到 entry 价上方 |
| **板块误判** | 板块方向判断错 | entry 时 sector_RS_rank_in_market 不在前 30%，或 30 日后跌出前 50% |
| **个股选弱（板块对了选股次了）** | 板块对但选了非龙头 | entry 时 RS_vs_sector_20d 排名不在板块内前 30% |
| **政策误读** | 政策落地不及预期或方向理解错 | 论点登记基于政策催化但 6 个月内未兑现 |
| **情绪干扰** | exit 主因是恐慌 / 贪婪而非 trigger | exit 触发原因 = 无 trigger 触发 |
| **持有过久** | trigger 已破损但仍持有 | trigger 破损 ≥ 5 日才 exit，或破损后净亏损扩大 |
| **提前止盈** | 趋势仍健康但已 exit | exit 时 trigger 全部 ✅ + 其后 30 日继续上涨 ≥ 10% |
| **仓位过重** | 信号强度 vs 仓位不匹配 | 单一论点仓位 > 25% 或单只票 > 15% 总资产 |
| **仓位过轻** | 论点对了但仓位太小 | 信号强度 ≥ 7 但仓位 < 5% |
| **加仓不当** | 加仓时机错 | 加仓时 trigger 已偏离 / 加仓价比 entry 高 > 20% |
| **重复同样错误** | 历史相同标签出现 ≥ 3 次 | memory 检索匹配同标签 ≥ 3 次 |

> 第 12 个标签 "重复同样错误" 是元标签，由系统自动检测，不由人为打。

## 3. 论点对照（与 M4 登记联动）

**关联论点**：`thesis_20260415_03`
- 原始命题："未来 1 个季度腾讯跑赢恒指 ≥ 5pp"
- 信号强度：7
- 登记 trigger（4 条）：
  1. ✅ 周线 MA20 上方
  2. ✅ 南向 5 日累计净买 > 0
  3. ✅ 沽空比率 < 15%
  4. ✅ 季度业绩在 5 月 14 日发布前不出意外

**Exit 时刻 trigger 状态**：4 条全部 ✅ 健康，**无 trigger 触发**

## 4. 决策质量评估

**结果**：盈利 +5.56%（vs 恒指 +1.2%），**结果好** ✅

**决策质量评分**：**5 / 10** ⚠

**评估**：
- ✅ entry 时论点清晰、trigger 设定合理
- ✅ 持仓期间未出现风险事件
- ❌ **exit 触发原因 = 无 trigger 触发** → 大概率情绪驱动
- ❌ 论点窗口（一个季度）远未到，季度业绩 5 月 14 日发布也没等
- ⚠ 仓位规模与信号强度（7 / 10）匹配，仓位本身没问题

> 注意：你这次"赚了"不代表"决策对"。如果今天卖出后腾讯继续涨到 410，你会少赚 6%；如果其他类似情境你不在这个对的票上 exit，平均结果会差。

## 5. 经验标签

主标签：**提前止盈** ⚠（trigger 全 ✅ + 论点窗口未到 + 主因情绪）

副标签：（无 — 这次只在 exit 时机出问题，其他维度都健康）

## 6. 学习要点（写入 memory）

1. **本笔交易揭示**：你的 trigger 设计合理，但执行时 trigger 没破你也会 exit。这是"情绪 exit > 机械 exit"的具体表现，与你之前自我诊断一致。
2. **可考虑机制**（仅供选择，不强加）：
   - 选项 A：entry 时同时登记一条 "minimum holding window" — 即使 trigger 未破，至少持有 N 天再考虑 exit
   - 选项 B：entry 时把 "情绪压力 = X" 显式写入 trigger 列表，把情绪当成可观测条件
3. **不需要的修正**：trigger 设定本身、仓位规模、论点逻辑都合理，不要为了这次 exit 调整其他维度。

## 7. 关联历史（memory 检索）

`memory/trade_log.jsonl` 中含 "提前止盈" 标签的历史交易：
- 2026-03-12 卖出阳光电源（持有 9 日，+8%，30 日后涨幅 +28%）— 提前止盈
- 2026-02-08 卖出宁德时代（持有 11 日，+6%，30 日后涨幅 +14%）— 提前止盈

⚠ **重复同样错误**触发：标签 "提前止盈" 已累计 **3 次**，系统提示这是结构性问题。建议下一次 entry 时主动把"提前止盈"防护机制写入 trigger 列表（参见学习要点选项 A/B）。

## 反模式

- ❌ **结果好就说决策对** — 决策质量与结果分离评估
- ❌ **结果坏就说决策错** — 同上
- ❌ **凭印象提取截图字段** — 看不清就明说
- ❌ **发明新经验标签** — 必须从 12 个 taxonomy 选；如真有新模式建议增加 taxonomy 而不是临时编
- ❌ **强加下次操作建议** — 提供选项不强推
- ❌ **跳过 M4 论点对照** — 每笔交易必须尝试关联 thesis_id；没有的话明说"未关联到论点"，提示 Patrick 是否 retroactively 登记
- ❌ **羞辱性语气** — 中立分析师视角，不评判人
- ❌ **不写 memory** — 每笔复盘必须更新 trade_log.jsonl，否则失去累积价值

## 与 M4 / M1 的协作闭环

```
M4 论点登记 ─→ memory/active_theses.jsonl
                       │
                       ↓
M1 盘前/盘后 ─→ 每日检查 trigger 状态 ─→ 报告 trigger 破损
                       │
                       ↓
Patrick 操作 ─→ 上传截图给 M3
                       │
                       ↓
M3 复盘 ─→ 与 M4 登记对比 ─→ 写入 memory/trade_log.jsonl
                       │
                       ↓
M3 检测 "重复同样错误" ─→ 标签累计 ≥ 3 次提示结构性问题
                       │
                       ↓
M4 下次论点登记时 ─→ 检索历史相似论点 + 经验标签 ─→ 提醒 Patrick 避坑
```

这个闭环是 SKILL.md "Trend integrity 监测，不强制纪律" 原则的具体落地：**事实闭环本身产生纪律，无需说教。**
